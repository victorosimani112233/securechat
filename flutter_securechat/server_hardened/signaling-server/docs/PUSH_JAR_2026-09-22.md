# Arka plan arama push JAR'i

## Kapsam

22 Eylul cihaz denemesinde `wake_no_hint` goruldu: Android'e ulasan wake
push'ta string `k` alani yoktu. Yerel kaynakta bilinen anahtar koruma ve
arka plan arama duzeltmeleri zaten vardi; aktif sunucunun bunlari kullandigi
henuz dogrulanmadi. Bu paket onceki aktif-JAR birlestirmesini korur ve
asagidaki yeni duzeltme/tani destegini ekler. Canli aramanin duzeldigi ancak
bu JAR kurulduktan sonraki iki-cihaz testiyle soylenebilir.

## Yeni degisiklikler

- `FcmPushSender.kt`: token kaydi bulunmayan deneme artik 3 saniyelik push
  hakkini tuketmez. Kayit hemen sonra geldiginde ilk gercek arama push'u
  engellenmez. Regresyon testi eski kodda basarisiz, yeni kodda basarili.
- Kayit okuma hatasi artik coroutine'den izsiz cikmaz; kimliksiz sonuc olarak
  sayilir. Hata metni/stack/token/anahtar loglanmaz. Bu regresyon da once
  basarisizdi. Eszamanli hiz siniri karari `ConcurrentHashMap.compute` ile
  atomiktir; normal mesaj/arama/kontrol kovalari ayri kalir.
- `FcmTokenStore.kt`, `HttpRoutes.kt`: kayit yaniti artik `status=ok` yaninda
  `pushHintRegistered` boolean'i ve `pushContract=encrypted-hint-v1` dondurur.
  Boolean, DB yazimi tamamlanan kaydin sonucudur; sonra yapilan ayri cache
  okumasindan turetilmez. Eski istemci halen 2xx/status ile calisir.
- `Metrics.kt`: yalniz sabit asama isimleri ve toplam sayilar tutan
  `securechat_fcm_diagnostic_total` eklendi. Kullanici, IP, token, arama
  kimligi, mesaj turu ve olay zaman damgasi etiketi yoktur. Sayaclar RAM'dedir,
  process yeniden baslayinca sifirlanir. Yetkili `/metrics` siniri korunur.
- `Application.kt` ve mevcut tani loglarina sabit protokol/surum isaretleri
  eklendi. Ancak normal `logback.xml` root seviyesi **ERROR** kaldi; INFO
  satirlarinin konsolda gorunecegi varsayilmamali. Genel log seviyesini acmak
  yerine asagidaki yetkili toplam sayac araci kullanilmalidir.
- `tools/collect_push_diagnostics.py`: mevcut operator anahtarini ortamdan
  veya `METRICS_BEARER_TOKEN_FILE` dosyasindan okuyup yalniz loopback uzerinden
  surum ve push sayaclarini getirir. Anahtari argv'ye, ciktiya veya gecici
  dosyaya yazmaz. HTTP yonlendirmesi/proxy/uzak hedef kabul etmez. Hata govdesi
  ve ham metrics dokumu ciktiya basmaz. Python 3 standart kutuphanesi yeterli.

## Korunanlar ve sinirlar

- Eski Kotlin uygulamasi, Flutter APK, E2EE protokolu, veritabani semasi ve
  kurulum scripti degismedi. Yeni migrasyon veya her push icin DB sorgusu yok.
- Token ve anahtar ayni sifreli kayitta birlikte saklanir/okunur. Ayni tokenin
  anahtarsiz yenilenmesi mevcut anahtari korur. Farkli token eski cihazin
  anahtarini devralmaz. Keyless eski/iOS kayitlarinin jenerik wake davranisi
  korunur; bu kayitlarin Android arama ekranini acacagi iddia edilmez.
- Mesaj-only baglanti ayrimi ve arama kontrol push'u icin ayri hiz kovasi
  onceki birlestirmeden dahildir. Aktif JAR'dan korunmus davranislar geri alinmadi.
- Yanlis veya eksik anahtar uydurulmaz; FCM'ye acik `c`/`m`, telefon veya
  arayan kimligi eklenmez. Gecersiz AES-GCM anahtarinda sifresiz fallback yok.
- Birden cok process'in token cache'lerini esitleme ve coklu-cihaz mimarisi
  eklenmedi. FCM kabul sayaci, cihaza teslim/ekran/cevaplama kaniti degildir.
- Dosyalar yerelde hazirlanmistir. Sunucuya aktarim, restart, commit/push
  veya veritabani temizleme yapilmadi.

## Kurulum ve tanilama

1. Mevcut calisan JAR'i yedekle. Yeni dosyayi once `.jar.new` olarak aktar,
   SHA-256 degerini dogrula, sonra mevcut JAR'in yerine atomik `mv` yap.
   Mevcut servis baslatma komutunu/ortamini koru. `KUR.sh` calistirma.
2. `collect_push_diagnostics.py` dosyasini sunucuda
   `/root/securechat/collect_push_diagnostics.py` konumuna aktar.
3. Mevcut sunucu ortamini yukleyip ilk raporu al. Komut, secret degerlerini
   ekrana basmaz; `set -x`, `env` veya ham metrics/token ciktilari paylasma.

```bash
set +x
cd /root/securechat
set -a
. /root/.securechat-dev/dev.env
set +a
python3 /root/securechat/collect_push_diagnostics.py
```

Arac mevcut `PORT` degerini, yoksa 8080'i kullanir. Raporun build commit
alaninda `dirty-pushdiag-20260922` gorulmeli. Bu bir Git commit'i degil,
calisma agacindan yapilan derlemenin acik etiketidir.

4. Android uygulamasini bir kez ac; yeniden kayit yapmasini bekle. Son
   uygulamalardan normal kapat, ekranini kilitle, diger cihazdan ara.
5. Ayni Python komutunu yeniden calistir. **Ilk ve ikinci JSON ciktilarini**
   birlikte paylas. Telefonun gorunur davranisini da belirt.

| Artan sayac | Anlami |
| --- | --- |
| `registration_hinted` | Kayit, anahtariyla basariyla kalici hale geldi. |
| `registration_keyless` | Kayit mevcut ama sifreli tur anahtari yok. iOS icin beklenebilir. |
| `wake_registration_unavailable` | Bu process'te token yok veya suresi dolmus. |
| `wake_lookup_failed` | Token kaydi okunamadi. |
| `wake_not_operational` | Firebase gondericisi baslatilamamis/yapilandirilmamis. |
| `wake_hint_missing` | Push hazirlanirken kayitta anahtar yok. |
| `wake_accepted_hinted` | Firebase sifreli `k` iceren push'u kabul etti. |
| `wake_accepted_keyless` | Firebase `k` icermeyen jenerik push'u kabul etti. |
| `wake_failed` | Sifreleme, payload veya provider gonderimi basarisiz. |
| `wake_rate_limited` | Ayni kovada 3 saniyelik hiz siniri. |

Bu sayaclar global toplamlardir; kalabalik canli sunucuda tek bir kullanici
denemesine kesin atif yapilamaz. Kimlik bazli log acmadan kontrollu test
penceresi ve telefon loglariyla karsilastirilmalidir.
